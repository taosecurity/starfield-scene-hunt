Finding where a Starfield scene comes from

A player saw a small site with people near a grave and flowers and asked whether it came from the Free Lanes update. This page shows, step by step, how we searched the game's plugin files for it, what each step found, and how you can run the same search for any scene you spot in Starfield.

By Richard Bejtlich, Richard Presents Starfield Essentials on YouTube

More Starfield tools and references are on the Richard Presents Development Hub.

Executive summary

  • Free Lanes adds exactly two grave sites: PIPCMManMade_SFFLPOI048 (three graves) and PIPCMManMade_SFFLPOI049 (seven graves). These are the only places Free Lanes puts a headstone.
  • Both are small procedural sites, so the game drops them at random spots when you land. You can't reach them with a coc command.
  • Neither site has people, a kneel marker or flowers in its files. The person kneeling in the player's photo is probably a separate encounter, a companion, the player in photo mode, or something from a mod.
  • We ruled out the base game's mourning content: the ID-card delivery mourners, the "Final Thoughts" audio slate, the hunted homesteaders, and the Waggoner Farm cemetery.
  • The method works for any scene: search for words, find the objects, list every place that uses them, then look at what sits next to each one.

The question

A player reported a small point of interest (POI) with three people near a grave marker or memorial with flowers, and wondered whether it came from the Free Lanes update. A later screenshot showed one figure in a spacesuit kneeling beside a single headstone, with a small bunch of flowers at its base. The question: which plugin adds this, and what is it called?

Every tool here only reads. None of them changes the game files.

Step by step

  1. 1

    Search the Free Lanes plugin for grave words

    Public tool

    What we did. We searched SFBGS00D.esm's raw bytes for grave, memorial, funeral, mourn, tomb, burial and flower.

    What it showed. Only the Tombstone weapon's parts and one companion comment turned up. A developer note on COM_Event_CommentTrigger_SFFLOETH01_01 says the companion remarks on many graves at that site.

    grep -a -o -i -E "[A-Za-z0-9_]*(grave|memorial|mourn|tomb|flower)[A-Za-z0-9_]*" SFBGS00D.esm | sort | uniq -c
  2. 2

    List Free Lanes' small encounters

    Public tool

    What we did. We listed the EditorIDs that look like encounter names: SFFLOE.. (planet overlay encounters), SFBGS00DDR.. and the POIs.

    What it showed. Ten SFFLOE encounters turned up. SFFLOETH01 is the graves site. SFFLOETH02 is a colony with a church, "New Babylon", which doesn't match.

    grep -a -o -E "SFFLOE[A-Z]{2}[0-9]{2}" SFBGS00D.esm | sort | uniq -c
  3. 3

    Look for mourning in the base game

    Game files

    What we did. We ran the same word search over Starfield.esm and the small official updates, then read each hit in the dump.

    What it showed. Three candidates turned up, and none fits. The mourner NPCs (Mourner, Mourner_UC01, Mourner_Freestar) belong to SE_Derelict_IDCardQuest, an ID-card delivery that takes place in New Atlantis, Akila and Cydonia. RQ_OE_Deliver_01 ("Final Thoughts") is a mining-site audio slate delivered to a widow in New Atlantis. OE_HuntedHomesteaders is a defend-the-camp encounter whose "dig graves" line is just dialogue.

  4. 4

    Find the objects a grave scene would use

    Game files

    What we did. We searched the dump for object records named like graves, headstones, memorials, flowers and kneeling.

    What it showed. This gave the FormIDs to follow: AK_Cemetery_Tombstone_01 (04B20D) and _02 (04B20C), the bouquet pack-in Bouquet_A01 (32EB16), the memorial easel, and the kneel and mourn markers NPCKneeling, NPCKneelingPraying, NPCKneeling_Planting and NPCStanding_Mourn.

  5. 5

    List every Free Lanes record that places those objects

    Public tool

    What we did. For each object we asked SFSearch which records in Starfield.esm and SFBGS00D.esm point at it.

    What it showed. Free Lanes places the headstones 4 times, the bouquet 0 times, the mourn marker twice (both inside ships) and kneel markers 23 times.

    SFSearch Live Starfield.esm 04B20D:Starfield.esm --refs --with SFBGS00D.esm --live
  6. 6

    Find the cell each headstone sits in

    Our script

    What we did. Placed objects don't say where they are, so cellwalk.py walked the whole plugin and recorded each object's cell.

    What it showed. Two headstones sit in an art-asset test cell (SFBGS00DWorldArtAssets). The other two sit at position 0,0,0 inside pack-in storage cells for SFFLPOI048 and SFFLPOI049. A position of 0,0,0 is the sign of a pack-in, a prefab group that other places reuse.

    python cellwalk.py SFBGS00D.esm 0106AE51,0106B135 out.json
  7. 7

    Open every layer of the grave sites

    Our script

    What we did. We listed the three layers of each site (see the next diagram) and the seven sibling sites, POI041 to POI047.

    What it showed. POI048 is three graves in a row, and POI049 is seven. Each grave is a headstone on a concrete slab with a debris pile, plus rocks, shrubs and one small loot item. Neither site has an actor, a marker or flowers. None of POI041 to POI047 has a grave.

    python cellwalk.py SFBGS00D.esm 0106AE51 out.json --cells 0106AE34,0106AE38,0106B130,0106B131
  8. 8

    Check the kneeling figure

    Our script

    What we did. The photo shows someone kneeling, so we found the cell of each of the 23 Free Lanes kneel markers.

    What it showed. They're all in dungeons, a factory and ship interiors (SFBGS00DDR001, DR009, DR010, DR015, SFFLDR023, SFFLOESM04, SFFLM03). None is near a grave.

  9. 9

    Check the base game's bouquets and headstones

    Game files

    What we did. We ran cellwalk.py over Starfield.esm for the 8 placed bouquets and the 4 placed headstones.

    What it showed. The bouquets are in cities and interiors (Akila, New Atlantis Mast, a Generdyne interior). The headstones are all at Waggoner Farm's cemetery on Akila (SettleWaggonerFarmCemetary). Neither is a small random site.

  10. 10

    Search the web

    Public tool

    What we did. We ran two web searches for player reports of a grave, flowers and a kneeling NPC.

    What it showed. Nothing matched, and the Free Lanes coverage doesn't mention it.

How a small site is built

Starfield builds a small procedural site out of nested pack-ins. The planet generator places the top layer, and each layer can place copies of the one below. To see everything a player might find, open every layer. Here are the layers of SFFLPOI048:

The seven-grave site, SFFLPOI049, places the same grave group seven times. The layer names come from the EditorIDs: PIPCMManMade_SFFLPOI048, GPPIPCMManMade_SFFLPOI048 and FPIPCMManMade_SFFLPOI048. The grave uses AK_Cemetery_Tombstone_01 and StructKit_Concrete_LgBase02, and each grave in the top layer gets a GenDebrisPile04.

Lessons for the next search

  • A raw text search is only a first pass. About 97,000 Starfield.esm records are compressed, and their names don't show up in a byte search. A reader that unpacks them (xEdit, SFSearch, cellwalk.py) sees everything.
  • Search for the objects, not the scene. A scene has no single record. Find its parts (headstone, flowers, kneel marker), then list every place that uses each part.
  • A placed object at 0,0,0 is inside a pack-in. Follow the layers up (FPI to GPPI to PI) to the site the planet generator places.
  • FormIDs inside a file start with the master index. In SFBGS00D.esm, 00 means Starfield.esm and 01 means Free Lanes' own records. In-game console IDs differ, because they depend on load order.
  • The xEdit dump covers one plugin. A Starfield.esm dump can't show what an add-on such as Free Lanes places. Use SFSearch or a reader for the add-on.
  • SFSearch input formats. Names takes FormIDs (04B20D), not EditorIDs. Live takes a six-digit FormKey such as 04B20D:Starfield.esm. Eight digits fail.
  • Ask about the person in the picture. A kneeling figure could be an NPC, a companion, or the player in photo mode (the game has a PhotoMode_Kneeling pose).

Open questions

The search ended with a strong lead but no proof. These steps would settle it:

  1. Ask the player for the planet, the site's name on the map or scanner, whether the kneeling person could be talked to, and whether they use mods.
  2. If they use mods, run the same object search (headstone, bouquet, kneel markers) over each mod's plugin.
  3. Open SFFLOETH01's cells with cellwalk.py to see how its graves are built.
  4. Confirm in game: land on a few planets, using a save without mods, until POI048 or POI049 appears, and see whether anyone turns up there.

Run it yourself

You need a copy of Starfield, Python 3 and, for the reference lookups, SFSearch. Run these from any folder. Change the path if your game is not in the default Steam folder.

set DATA=C:\Program Files (x86)\Steam\steamapps\common\Starfield\Data
rem 1. Words in the plugin (first pass)
grep -a -o -i -E "[A-Za-z0-9_]*(grave|memorial|mourn)[A-Za-z0-9_]*" "%DATA%\SFBGS00D.esm" | sort | uniq -c
rem 2. Which Free Lanes records place the headstone 04B20D
SFSearch Live Starfield.esm 04B20D:Starfield.esm --refs --with SFBGS00D.esm --live
rem 3. Which cell holds those records, and what else is in it
python cellwalk.py "%DATA%\SFBGS00D.esm" 0106AE51,0106B135 out.json
rem 4. Names for the base objects in out.json
SFSearch Names "1FFE18 1F3EAF 23336B" --in Starfield.esm --live
cellwalk.py (MIT licence)
"""cellwalk.py - find which cell holds a placed object in a Starfield plugin, and list what else is in that cell.

Read-only. It reads one .esm file, unpacks compressed records, and never writes to the game folder.

Usage:
    python cellwalk.py <plugin.esm> <ref ids> <out.json> [--cells <cell ids>]

    <ref ids>    placed-object FormIDs as stored in the file, comma separated, 8 hex digits
                 (the first two digits are the master index: in SFBGS00D.esm 00 = Starfield.esm, 01 = its own records)
    <out.json>   where the full listing goes
    --cells      also list these cells, by FormID, even if no ref id points to them

Example:
    python cellwalk.py "C:\\Program Files (x86)\\Steam\\steamapps\\common\\Starfield\\Data\\SFBGS00D.esm" 0106AE51 out.json

For each ref it prints the cell FormID and EditorID and how many objects are in it. out.json holds every object in
those cells: record type, FormID, base FormID, EditorID if the plugin names it, and position.
"""
import argparse
import json
import struct
import sys
import zlib

REF_TYPES = (b"REFR", b"ACHR")
CELL_GROUPS = (6, 8, 9, 10)  # GRUP types that belong to one cell: children, persistent, temporary, (exterior) children


def subrecords(buf):
    i, big = 0, None
    while i + 6 <= len(buf):
        t = buf[i:i + 4]
        sz = struct.unpack_from("<H", buf, i + 4)[0]
        i += 6
        if t == b"XXXX":  # next subrecord is bigger than 65535 bytes
            big = struct.unpack_from("<I", buf, i)[0]
            i += sz
            continue
        if big is not None:
            sz, big = big, None
        yield t, buf[i:i + sz]
        i += sz


def main():
    ap = argparse.ArgumentParser(description="Find the cells that hold placed objects in a Starfield plugin.")
    ap.add_argument("plugin")
    ap.add_argument("refs", help="comma-separated FormIDs, 8 hex digits as stored in the file")
    ap.add_argument("out")
    ap.add_argument("--cells", default="", help="comma-separated cell FormIDs to list as well")
    a = ap.parse_args()

    try:
        targets = {int(x, 16) for x in a.refs.split(",") if x}
        extra = [int(x, 16) for x in a.cells.split(",") if x]
    except ValueError:
        sys.exit("cellwalk: FormIDs must be hex, for example 0106AE51")
    try:
        data = open(a.plugin, "rb").read()
    except OSError as e:
        sys.exit(f"cellwalk: can't read {a.plugin}: {e.strerror}. Check the path to the .esm file.")
    if data[:4] != b"TES4":
        sys.exit(f"cellwalk: {a.plugin} doesn't start with a TES4 header, so it isn't a plugin file.")

    edids, cells, hits, bad = {}, {}, {}, 0

    def walk(start, end, stack):
        nonlocal bad
        i = start
        while i < end:
            sig = data[i:i + 4]
            size = struct.unpack_from("<I", data, i + 4)[0]
            if sig == b"GRUP":
                label, gtype = struct.unpack_from("<Ii", data, i + 8)
                walk(i + 24, i + size, stack + [label] if gtype in CELL_GROUPS else stack)
                i += size
                continue
            flags, fid = struct.unpack_from("<II", data, i + 8)
            body = data[i + 24:i + 24 + size]
            if flags & 0x40000:  # compressed: 4-byte unpacked size, then zlib
                try:
                    body = zlib.decompress(body[4:])
                except zlib.error:
                    bad += 1
                    body = b""
            edid = base = pos = None
            for t, v in subrecords(body):
                if t == b"EDID":
                    edid = v.rstrip(b"\0").decode("utf-8", "replace")
                elif t == b"NAME" and sig in REF_TYPES and len(v) >= 4:
                    base = struct.unpack_from("<I", v)[0]
                elif t == b"DATA" and sig in REF_TYPES and len(v) >= 12:
                    pos = [round(x, 1) for x in struct.unpack_from("<3f", v)]
            if edid:
                edids[fid] = edid
            if sig in REF_TYPES and stack:
                cells.setdefault(stack[-1], []).append((sig.decode(), fid, base, edid, pos))
                if fid in targets:
                    hits[fid] = stack[-1]
            i += 24 + size

    walk(24 + struct.unpack_from("<I", data, 4)[0], len(data), [])
    for c in extra:
        hits[c] = c

    res = {}
    for t, c in hits.items():
        refs = cells.get(c, [])
        res[f"{t:08X}"] = {
            "cell": f"{c:08X}", "cell_edid": edids.get(c),
            "refs": [[s, f"{f:08X}", f"{b:08X}" if b is not None else None, e or edids.get(b), p]
                     for s, f, b, e, p in refs],
        }
        print(f"{t:08X} in cell {c:08X} {edids.get(c) or '(no EditorID)'}: {len(refs)} objects")
    with open(a.out, "w", encoding="utf-8") as f:
        json.dump(res, f, indent=1)
    missing = sorted(targets - set(hits))
    if missing:
        print("not found:", ", ".join(f"{m:08X}" for m in missing))
    if bad:
        print(f"warning: {bad} compressed records could not be unpacked")
    print(f"full listing: {a.out}")


if __name__ == "__main__":
    main()
